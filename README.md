# MapleBowmanVision — 使用手册

这是给 **NewMaple** 和原 **经典版 / 怀旧服冒险岛** 使用的视觉挂机助手，目前包含弓箭手、飞侠·标飞、原地攻击与战士·龙骑士的龙咆哮策略。两个客户端使用彼此隔离的配置与采集素材，不会混用窗口校准或模板。

它只看屏幕像素，再模拟键盘。不读游戏内存、不抓包、不注入。能不能挂机以你所在服的规则为准。

适合：单层横向平台、站着射怪。不适合：爬绳、跳台、自动换图、组队复杂场景。

开发者或用 AI 改代码，请看 [AGENTS.md](AGENTS.md)。

### NewMaple 狩猎验证人工提醒

面板固定外层提供“狩猎验证”开关，仅检测并响铃、不暂停挂机，切换任何页签都可操作；默认关闭，开启后持久保存到当前档案。可先点“试听验证提示音”确认声音和音量可用：高低双音交替，重复约 10 秒后自动结束，不修改系统音量。检测、开关切换和响铃都不改变挂机状态，不输入聊天、不识别数学题或提交答案；手动输入前请自行暂停挂机并关闭自动喝药，避免游戏按键混入聊天。

这是基于提供截图的聊天字形匹配，不是通用 OCR：每 0.5 秒检查一次左下聊天区，连续 3 次命中“【狩猎验证】”后异步播放一段 10 秒提醒音。提示持续存在或在聊天区滚动不会重复触发新一轮声音；连续消失 10 秒后重新监听，两次提醒至少间隔 60 秒。重新开启时屏幕上的旧提示也可能触发，不能据此判断验证是否仍有效。聊天隐藏、字体/颜色改变、遮挡或截图缓存可能导致漏报或过时提醒；只识别到画面文字，不判断验证成功。

默认聊天区域为客户区归一化坐标 `verification_alert.chat_region = {"x":0,"y":0.65,"w":0.5,"h":0.27}`，适配提供的 1280×720 截图；布局改变时可退出助手后在当前档案配置中调整。支持原生及几种常见字形缩放，但不保证任意字体/DPI。成功提醒记录在原有 `logs/session-*.jsonl` 的 `verification_alert` 事件中（时间、固定关键字、匹配分数、仅提醒标记），不保存题目或答案。没有实时截图时不能检测；提示音仍受系统静音/音效配置影响。

## 1. 安装

需要 **Windows** 和 **Python 3.10+**。电脑上如果只有 3.7，直接装依赖会失败。

1. 双击 `Setup.bat`。
2. 若提示下载 Python 3.12，等它装完即可（只装给当前用户，不会替换系统里的旧 Python）。
3. 第一次启动时会自动创建所选客户端的个人配置，不会覆盖已有配置。NewMaple 使用 `profiles/newmaple/config.json`，原怀旧服继续使用根目录 `config.json`。

之后日常只运行 `Start.bat`，不必反复 Setup。

---

## 2. 启动

可以先启动助手，游戏尚未打开也能进入控制面板。

整个项目只有一个日常启动入口：双击 **`Start.bat`** 使用 NewMaple 档案。如需使用原怀旧服，在命令行运行 `Start.bat classic`；也可显式运行 `Start.bat newmaple`。启动时会弹出一次 UAC；选择“是”后进入控制面板，但不会自动连接或挂机。

1. 打开游戏并保持 **窗口模式、未最小化**。
2. 在“窗口连接”页签的作用窗口列表中选择实际游戏窗口，必要时点“刷新”，再点“连接”。原配置匹配的窗口会作为默认候选；多个同名窗口会区分显示。
3. 确认校准与模板后，再点“启动挂机”或按 F8。仅连接窗口不会开启挂机或自动喝药。

采集、校准、识别和按键都使用这次选择的窗口。切换或断开会先暂停并释放按键、关闭自动喝药，之后必须手动重新启动；目标关闭或最小化时会断开并保留面板，恢复后重新连接即可，不会自动改连另一个同名窗口。无连接时仍能调整配置、管理已有模板。

原参数和校准作为默认值保留，不会因选窗被清空；如果换成不同尺寸或界面布局，请重新校准。选择成功后只记住标题和程序名供下次预选，不保存临时句柄或进程号。独立命令行采集及 `--overlay-only` 仍按配置查找目标。

NewMaple 的配置和素材都保存在 `profiles/newmaple/` 下；原怀旧服仍使用根目录 `config.json` 与 `assets/`。首次切换到 NewMaple 后需要重新完成校准和模板采集，这是有意的隔离设计。

## 3. 第一次校准（必须）

从 `Start.bat` 启动后，控制面板和游戏始终是两个独立窗口。面板采用参考 macOS 的灰白与系统蓝主题、圆角分组和分段式页签，使用 Windows 清晰可用的中文字体；通过顶部横向页签按功能切换，不会移动、缩放或停靠游戏；点击采集后，框选层会直接覆盖到游戏原窗口上。每个项目独立采集、独立保存，某项取消或失败不会清空其它项目。

工具窗口使用 BeiDou 素材库中的花蘑菇图标，来源见 [图标说明](resources/README.md)。更换后需退出并重新启动工具；`Start.bat` 文件本身仍显示系统默认批处理图标。

- **窗口连接**：选择作用窗口、刷新、连接和断开。
- **区域校准**：血蓝条、小地图、玩家标记、战斗识别区与索敌范围。
- **模板采集**：怪物分类、过滤项，以及姓名板、头部、称号的增删管理。
- **职业策略**：职业、策略与专属参数、通用索敌范围数值。
- **按键补给**：游戏按键、喝药阈值、定时 Buff 和人工提醒。
- **运行设置**：识别与行为参数、按键投递方式、置顶等选项。
- **性能监控**：FPS、分段耗时和 CPU/内存详情。

窗口连接集中在独立页签，启动/暂停、自动喝药、狩猎验证、识别框及保存操作固定在外层。参数较多的页签只在本页滚动，换页保留设置与滚动位置，不影响运行状态。窄窗口自动使用“校准/模板/策略/补给/设置/性能”等短页签名，拉宽后恢复完整名称，不缩小字体。

每个采集行的“显示”只会画当前项目；F7 和底部 Debug 开关用于全部显示或全部隐藏。“模板采集”分为“怪物模板”和“人物模板”，玩家姓名板、头部和称号勋章都归在人物模板中。

1. **分别采集血条、蓝条、小地图和小地图玩家标记**
   每行都有“显示”和“采集/重采”。先框小地图内部，再单独点击自己的小地图标记；玩家标记采集时会冻结画面、压暗其它区域并把小地图最高放大 8 倍，点击会映射回原图，只分析点击附近连续、明亮的标记像素。保存前会确认该颜色只命中点击位置，并记录初始位置供启动首帧消歧；姓名板、头部和称号暂时都看不见时，这个实时标记也可用于判断角色是否仍在上次视觉位置。重采小地图后只需重新确认玩家标记。
2. **分别采集战斗识别区域和小地图平台安全点**
   战斗区框选 **几乎整个可见战斗场景**（可排除底栏和聊天）。平台安全点采集会冻结画面并放大小地图，点击目标平台上希望角色返回的中心位置；它只在需要回位的职业策略中作为必要项。重采小地图后需要重新采集玩家标记和平台安全点，重采战斗区不会影响平台安全点。
3. **建立怪物分类，再采集怪物模板** 3～6 张
   在“当前识别分类”中选择或新建分类；助手只会加载并识别当前选中的分类，切换后立即生效，并记住到下次启动。工具会 **先冻结当前画面**，请在这张静止图上框住一只没被挡住的怪，四周可以多留一些背景，程序会分离主体后自动紧裁，换动作再采几张。新模板会保存透明怪物主体；只有完全无法区分怪物与背景时才会提示重新框选。分类和单张模板都可在面板中删除；管理窗口会显示图片预览，连续删除时不会关闭。删除的文件会移入当前档案的 `assets/template_trash/`。
   如果木板、特效或场景装饰经常被当成当前分类的怪物，选择该分类后点 **采集过滤项**，紧贴框住这个错误目标。过滤项只会排除同分类、同位置的候选。
4. **采集姓名板**
   同样在静态帧上，紧贴框选自己姓名板第一行蓝底（含名字和两端装饰），不要框到角色、宠物或别人；确认模板后继续在同一静态帧点击自己双脚落点中心。
5. **采集头部**、**采集称号勋章**
   各 1～2 张，每张确认后同样点击角色脚底。换发型或换称号后请删除过期模板并重采，避免旧外观匹配到附近玩家。
6. **框选通用索敌范围并选择职业与策略**
   通用索敌区供使用公共范围的策略共享；龙咆哮使用自己框选的攻击范围。先选职业，再选该职业的基础策略，并用复选框启用可组合的策略模块；下方会显示对应说明、参数和专属采集项。

改完攻击键、药键等数字项后，点 **保存配置**。按键也可以点输入框旁的「采集」，然后在游戏画面上按一下真实按键。

所有会保存成图片的采集项都可以管理。“怪物模板”中管理怪物与过滤项，“人物模板”中管理姓名板、头部和称号勋章；管理器使用两级分类切换，可预览、新增或删除单张图片。怪物和过滤项使用面板当前选中的怪物分类；删除不会直接销毁文件，而会移入当前档案的 `assets/template_trash/`，需要时可手动移回原类型目录恢复。删除最后一张姓名板后，必须重新采集姓名板才能启动挂机。

## 4. 看懂游戏上的框

| 颜色 | 含义 |
|---|---|
| 青色 | 玩家定位（姓名板 / 头部 / 称号） |
| 紫色细框 | 识别到的怪物候选 |
| 绿色粗框 | 当前攻击或接近的目标 |
| 黄色框 | 所有职业策略共享的有效索敌区，会跟着角色位置和面向移动 |
| 绿色圆点 | 小地图上的自己 |
| 橙色虚线玩家框 | 小地图标记保持静止时，短时沿用的上次可靠视觉位置 |

面板中的“显示 Debug 框”按钮或 **F7** 控制全部识别框的总显隐；默认显示全部框，各采集项与策略区域旁的“框：开/关”按钮可以独立控制对应框。切换总开关不会清除单项选择。采集工具打开时 HUD 会整窗收起，互不影响。

确认：青色框在自己身上，黄色索敌区覆盖你想射的距离，怪物走进黄框会变成绿框。小地图平台安全点只供策略内部寻路，不在 HUD 上显示。

姓名板候选会在原始分辨率进一步核对本人名字字形；姓名板曾确认本人但普通视觉保持已超时后，还会在最后预测位置附近用较低的原始匹配阈值尝试恢复，候选仍必须通过本人名字核验、位移限制和连续两帧确认，首次全图认人不会降低阈值。姓名板确认本人后，头部和称号也可在预测位置附近连续补位。每次可靠姓名板命中，以及本人身份已由姓名板建立后的连续头部命中，都会固定记录同帧的小地图本人标记。若姓名板和头部随后都未命中、称号也没有提供有效位置，当前唯一标记与这个固定基准相差不超过 2 个小地图像素，助手会在最多 0.2 秒内判断角色仍在原地并短时沿用上次视觉位置；静止帧不会刷新计时。标记移动、缺失、多重命中、尺寸变化或超时会在同一帧清除位置并暂停选敌和攻击，移动后即使回到原点也必须先重新取得视觉命中。程序刚启动且从未由姓名板确认过本人时不会启用这条路径。新采模板使用各自记录的脚底点，旧模板继续兼容固定偏移。

半分辨率粗检没有通过姓名身份校验时，会在相同搜索区域追加原分辨率模板匹配，解决移动或回位后细字因像素对齐变化而漏检的问题；复核仍使用正常阈值及身份确认，不靠降低识别标准恢复攻击。“小地图已定位，等待画面定位恢复”只代表导航位置可用，尚不能确认主画面的攻击锚点。

## 5. 开始挂机

1. 角色站在目标平台上，面向你要清的方向。
2. 点击控制面板中的 **启动挂机**。UAC 已在启动 `Start.bat` 时完成，面板不会关闭或重启。
3. 角色应开始走位、转向、攻击、补药。
4. **暂停**：再点「暂停挂机」或按 **F8**。  
   **退出**：面板「退出程序」、HUD 右上角按钮、**F9** 或 **Ctrl+Shift+Q**。

建议勾选「后台按键」：点面板不会抢走游戏焦点。默认同时勾选「挂机时强制游戏窗口置顶」，启动后会置顶游戏，暂停或退出时恢复；如果希望游戏和工具完全独立，可取消该项。取消置顶并使用后台按键时，启动挂机不会抢前台；无论是否置顶，游戏窗口仍须 **可见、未最小化**。

### 龙咆哮定点攻击

在“职业策略”选择 **战士·龙骑士 → 龙咆哮·定点**：

1. 点“采集龙咆哮定点”，在放大的小地图点击希望站立的位置。
2. 点“新增龙咆哮攻击范围”，角色定位有效时框选技能覆盖范围。范围跟随角色、不随面向翻转；支持重框、增删和启用/禁用，多个框取并集，不重复计算重叠处的怪物。
3. 采集龙咆哮技能键，设置怪物数量阈值与施放间隔。默认阈值 **2**，意味着范围内本帧至少 **3 只**才施放；技能键留空不攻击，不使用普通攻击替代。
4. 调整定点水平/垂直容差（小地图宽/高比例），确认模板和小地图标记后再启动。

角色偏离容差后优先回位，回到较小范围内才恢复输出；不追怪、不定时走动、不自动拾取。只剩可信小地图定位时可回位，但必须等主画面人物定位恢复才施法。完全丢失定位会等待，不左右盲走。

回位适用于可直接走回或跳回的点，不具备绕障碍、爬绳或跨地图寻路。持续没有位移会暂停，单次回位默认 15 秒超时后停住，检查路径后需暂停再启动。重采小地图要重采定点，重采战斗区要重框攻击范围；原有策略配置不会被覆盖。

## 6. 键位

连接窗口后，助手提供以下固定热键；尚未连接时可用面板按钮退出：

| 功能 | 键 |
|---|---|
| 显隐 Debug 框 | F7 |
| 启动 / 暂停 | F8 |
| 立即退出 | F9 或 Ctrl+Shift+Q |

游戏内按键在面板「参数设置」或当前档案 `config.json` 的 `keys` 里改。怀旧服示例默认：攻击 `Shift`，跳跃 `Alt`，拾取 `Z`，HP `Home`，MP `End`，移动左右方向键，下跳方向键为 `Down`；NewMaple 独立档案的跳跃键初始为 `Space`。支持字母、数字、Ctrl、Shift、Alt、Home、End、PageUp、PageDown 等。

## 7. 常用设置

挂机配置现在会自动保存：`−/+`、HP/MP 滑杆、复选框和职业策略选择在运行时修改后都会写入当前档案的 `config.json`；退出程序前还会完整保存一次当前界面值。“保存配置”按钮可用于立即确认并应用全部字段。

配置保存使用原子替换，写入失败会保留原文件；上一份不同的可解析配置保存在同目录 `config.json.bak`。内容未变化的自动保存和退出保存不会重写配置或覆盖备份。如需恢复，请先退出助手，再用备份替换当前配置。

定时 Buff 的停攻准备期可以处理暂停、关闭单项和按键修改；准备取消不消耗冷却。多个 Buff 到期时按最早到期顺序补放，短间隔项目不会持续抢占其它项目。前台模式发键前复核焦点，独立后台模式继续支持失焦补 Buff。

- **性能监控**：独立“性能监控”页每秒刷新实际 / 目标 FPS、整帧平均和 P95 耗时、超预算比例、进程 CPU、内存及截图/识别/决策等分段耗时；CPU 按系统全部逻辑处理器容量归一为 0～100%，与任务管理器口径一致。整帧耗时不包含为了限制 FPS 而主动等待的时间；“决策/输入”会包含跳跃攻击等动作本身的短暂等待。暂停挂机但全局自动喝药开启时，没有执行的怪物、玩家识别阶段显示 `—`，属于正常现象。点卡片右侧 `×` 可折叠，之后可点“显示性能监控”恢复，状态会自动保存。
- **帧率调整**：修改并应用截图 FPS 后，从下一帧更新实际节流预算与监控目标，最低为 2 FPS，无需退出重开。实际帧率仍受截图、识别和动作耗时限制。
- **玩家定位续认**：姓名板确认过本人后，攻击、Buff 或短步动画造成普通视觉保持超时时，头部/称号仍可在最后可靠位置附近连续三帧恢复定位；默认只允许在 15 秒内这样续认，不会用远处候选换锁。当前帧头部/称号或有效小地图静止补位仍可定位时，不会仅因姓名板消失就左右移动找人。
- **小地图主导航与遮挡辅助定位**：勾选面板同名开关后，已确认本人且曾与唯一实时小地图标记配对时，三路视觉丢失仍可按小地图回安全点，到位后等待画面恢复；默认最多导航 10 秒。小地图坐标不直接换算屏幕坐标，只有地图位置时不攻击、追怪、拾取或启动新短步。旧静止补位维持 2 像素／0.2 秒；超过后必须同时满足固定标记位移不超过 0.5 像素、固定背景 12 个分块中至少 7 个分散纹理块仍稳定，才能沿用屏幕锚点最多 3 秒。时限都从真实视觉证据计时，不滚动刷新；镜头滚动、大面积特效或纹理不足会拒绝延长。面板可直接输入“遮挡静止补位秒”（0–5）与“遮挡导航最长秒”（0–30），设 0 分别禁用延长补位或无视觉导航。窗口截图被客户端缓存时仍无法据此证明画面实时，需实测。
- **职业与策略**：先按职业筛选基础策略，再多选该策略的功能模块。“原地攻击”平时偏离小地图安全点也优先回位；每隔 45 秒停攻后向右短走一步，确认位移并回位后再继续输出。小步最多尝试三轮，普通回位连续 4 秒无进展会暂停并提示，不再把“按键已发送”当作“已经移动”。“标飞安全输出”包含可独立开关的近目标跳跃攻击、近身重叠跳跃攻击和安全区回位。
- **弓箭手动态技能选择**：策略面板可分别采集 AOE、单体、近身技能键。怪物贴近玩家时优先使用近身技能，并采用独立的进入/退出距离倍率避免来回切换；否则当前目标附近达到“AOE 最少怪物数”时使用 AOE，其余情况使用单体技能。距离由当前怪物检测框自动换算成怪物体型倍数，会随模板和分辨率缩放；AOE 或近身键留空会跳过对应模式，单体键留空则沿用通用攻击键。
- **原地攻击转向**：首次输出、换边和移动后，不再单凭缓存方向跳过转向；距上次攻击至少 0.6 秒后，按 behavior.face_tap_seconds 独立短按方向（下限 0.02 秒，默认 0.025 秒），再等 0.08 秒并在后续帧复核目标才攻击。无目标、原地等待、拾取不再反复重置转向；短于 0.5 秒的视觉丢失仍停止攻击，但恢复后保留刚发过的转向，不额外停攻重转。连续视觉丢失达到 0.5 秒（含恢复首帧）或地图标记不可信时仍作废朝向记录。所有输入模式同侧持续输出均不再每 5 秒强制停攻刷新；动态和原地普通攻击均不再每次按住方向。普通喝药、Buff 准备与施法保护不再单独重置方向（绑定移动/跳跃键除外）；保护时长与识别门禁不变。必要转向仍可能有微小位移，缩短按键后需实测客户端是否接受。HUD“向左／右攻击”表示请求的输出方向，不是角色朝向的视觉识别；日志明确记录未验证实际面向。纯独立后台仍用消息转向、不回退全局输入；混合后台仅在游戏已经前台时扫描码转向，后台不切窗、沿用当前朝向发技能，见下方输入模式说明。仅“前台按键”在拾取／回位等实际移动后恢复普通攻击时加强交接：松开拾取与左右键后跨帧等待 0.12 秒且目标仍同侧，短按方向至少 0.08 秒，再等 0.12 秒恢复输出；较长配置保留，同侧后续攻击不额外等待。此加强不改变其他输入模式，可能有短按导致的少量位移，仍需实测实际转身。
- **拾取清怪方向稳定**：路线清怪优先清当前侧，该侧连续 0.4 秒没有有效目标才换边，避免两侧怪物距离变化引起频繁转身。前台按键模式在整段路线清怪中，每次必要转向都使用上述加强交接，同侧连续攻击不额外停顿；混合后台仍不为战斗转向抢前台。返程清怪短暂丢失视觉时也先停走等待定位宽限，不立即插入回家移动。
- **原地攻击近身技能**：选中“原地攻击”后，独立采集“近身技能键”，当前同层目标靠近时使用，远离后恢复通用攻击键。进入／退出距离默认是怪物宽度的 `0.35`／`0.9` 倍，可直接输入调整；清空技能键即关闭。安全点回位、定时右移和药/Buff 仍保持原优先级，不新增追怪或持续移动。
- **原地定时路线拾取**：在原地策略中点击“采集目标拾取点”，像安全点一样在冻结放大的小地图上点选（需要同一平台、路径可步行，不能选在安全点回位半径内）；确认通用“拾取键”与游戏绑定一致，再开启“定时路线拾取（同平台）”。默认启动挂机后每隔 180 秒出发，数字可直接输入；去程、到点和正常返程均使用当前索敌范围，遇可攻击怪物先原地清理（含近身技能），期间停走、停拾取，不追怪。连续无有效目标 0.4 秒后再继续，避免单帧漏检就走开；这是视觉消失确认，不是真正检测死亡。到点前最长秒默认 90 秒，到点阶段最长秒默认 60 秒（含清怪），到期切换返程意图，但正常返程仍先清怪，因此持续刷怪可能延后到家。到点有效拾取秒默认 1.5 秒，清怪、无目标确认、药/Buff、定位等待不计入有效拾取；相关参数仍可直接输入。实际往返到家且清怪结束后，拾取间隔与右移间隔重新计时（右移默认 45 秒）。关闭开关、点位失效、掉层或定位异常仍优先安全返回，不为清怪停留；F8 暂停立即抬键，不继续回位。
- **路线拾取限制**：去程、到点停留及返程的有效拾取阶段持续按住通用拾取键，不再每 0.15 秒点按；长按期间约每 0.1 秒模拟键盘自动重复的按下事件，中途不松键，遇怪清理、药/Buff、定位丢失、路线分段、结束或暂停时松开。正常帧持续续期，超过约 0.8 秒没有行动续期则自动松键（另有线程调度误差）；未检测地上物品或背包，不能保证物品全部入包。拾取键不能与左右移动、下蹲或跳跃冲突。小地图重采会使拾取点失效，战斗识别区重采不会；换地图须重采安全点和拾取点。定位短暂丢失先停走、停攻、停拾取，默认等待 1 秒（“拾取定位丢失等待秒”，可调 0.2–3 秒）；及时恢复继续原路线，持续丢失则转为返程。返程仍需可信位置，完全丢失或小地图歧义时保持停止，绝不盲走；原小地图导航总时限不延长。掉层、关闭功能及点位失效仍优先回位。混合后台的路线移动每约 2.5 秒主动抬键但不切回原窗口，至少等待 0.7 秒后复核空闲与焦点再进行下一段；仍保留 4 秒移动会话时限、心跳、用户打断和位移无进展保护。纯 PostMessage 不接受移动的客户端仍不能完成路线；混合后台也不是完全无打断。
- **标飞安全输出位置**：安全区默认关闭且不是必要采集项；启用后在放大的小地图上框选，运行时用小地图玩家标记判断位置，不受战斗镜头滚动影响。“安全输出区内无目标时巡逻”是默认关闭的可选项，关闭时进入安全区后原地索敌。旧的战斗画面安全区会自动失效，需要重新框选。
- **标飞多索敌区**：每个区域跟随角色位置移动，但保持屏幕方向，不随角色面向左右翻转；旧的屏幕固定区域需要重新框选。
- **姓名板丢失恢复**：超过视觉保持时间且没有可靠画面定位或小地图主导航可用时，才回退交替左右位移；可调整单向位移秒数或关闭。小地图主导航超时会停止动作等待，不转入盲目位移。
- **标飞近身跳跃攻击**：默认开启。怪物与角色的水平重叠达到 20%（可调）时，按 `Alt`，0.05 秒后按 `Shift`，保持 0.05 秒后按相反顺序释放；关闭模块后恢复普通飞镖攻击。
- **标飞近目标每次跳跃攻击**：默认开启。目标中心与角色稳定锚点的水平距离不超过 120 像素（可调）时，每次攻击都先跳跃；攻击间隔沿用公共攻击间隔。
- **索敌区前方 / 后方 / 上方 / 下方**：这是所有职业策略共享的参数，一般用「框选通用索敌范围」，不必手填。
- **怪物轮廓权重**：默认 `0.15`，用于抑制颜色相近但轮廓不同的树干、地形等空气误框；过高可能漏掉动作变化较大的怪物。
- **策略数值微调**：面板为了不抢游戏焦点，使用字段右侧的 `−` / `+` 按钮修改，每次调整 `0.01`；黄色索敌框会实时预览，并立即保存到当前档案的 `config.json`，重启不会丢失。
- **小地图平台安全半径**：小地图玩家标记超出平台安全点左右这个距离后，“弓箭手动态”会优先回位。数值是小地图内部宽度的比例，例如 `0.12` 表示左右各 12%。
- **没有目标时左右巡逻**：单层图可开；多层图容易走下平台，默认关。
- **目标丢失后拾取一次**：掉物多再开。
- **HP / MP 阈值滑杆**：低于该比例自动喝药；可直接用鼠标拖到 0～100%，也可用两侧按钮每次微调 1%，不需要键盘焦点。
- **全局自动喝药**：这是会话开关，默认关闭。关闭后挂机运行和暂停状态都不会发送 HP/MP 药键；开启后挂机运行时按阈值补药，暂停状态仅在游戏位于前台时补药，并跳过怪物、姓名板等战斗模板识别以降低 CPU 占用。
- **3 组定时补 Buff**：每组都有独立启用开关、按键和间隔秒数。关闭单项会保留它的按键与间隔，重新开启即可恢复；点击间隔右侧的“输入”可直接键入数字，也可用 `−` / `+` 微调。程序首次启动挂机时立即施放，之后按各自间隔补放。F8 暂停、失焦暂停和配置刷新会保留计时，重新启动时只补已经到期的项目，避免技能尚在冷却却被误记为已补。每次施放会先停攻片刻并使用较长按键，多个同时到期的 Buff 会依次错开。按键留空或间隔设为 `0` 也会关闭单项，暂停时不会发键。
- **下拉框滚轮保护**：怪物分类、职业、基础策略和策略选项不会响应鼠标滚轮，滚动面板时不会误改选择。
- **最长运行分钟**：`0` 表示不限时。
- **输入模式**：底部可选“前台按键”“兼容后台（全局按键）”“独立后台（实验）”“混合后台（移动后留前台）”。兼容后台仍发送全局扫描码，可能影响你正在操作的其它窗口；混合后台在游戏前台用扫描码发普通技能，后台用窗口消息；实际移动可切前台，战斗转向只能借用已有前台、不主动切窗。
- **混合后台（移动后留前台）**：`input.delivery=hybrid`。攻击、近身技能、Buff、喝药、拾取及跳攻的技能键，游戏前台用 `SendInput`、后台用 `PostMessage`，每次按下与抬起固定原通道。后台攻击不再为了转向主动激活游戏，也不补发无效方向消息；沿用游戏当前面向，HUD 显示“后台沿用游戏当前朝向攻击（未转向）”。因此怪物在另一侧时可能打不到，不能同时保证后台不打断与自动可靠换边；可先在前台选好面向再切走。游戏已在前台时正常按配置短按转向（0.02–0.1 秒，默认 0.025 秒），输入层禁止转向重新抢回焦点。周期右移、拾取往返、安全回位及策略需要的实际追踪/导航仍可切到前台，结束后不自动返回旧窗口；后台完全丢失定位时等待恢复，不左右走动找人。识别门禁、技能节奏和位移验证保持不变，不影响其它模式。实际移动仍须观察按键/鼠标按钮释放后空闲 0.7 秒、复核 HWND/PID 与焦点、等待新视觉帧，鼠标纯位移不阻断；取消、切窗、输入错误照常抬键保护。游戏需保持非最小化并支持窗口截图，转向实际效果仍需游戏实测。
  单次前台移动会话最多 4 秒（不含切窗耗时），单次按键无新帧续期最多保持 0.5 秒，行动心跳中断超过 0.8 秒停止；独立保护线程约每 20 毫秒检查一次，F8/F9 也会取消。用户按其它键、点击或切换窗口时终止移动，不再抢回旧窗口；激活失败、输入异常或移动无进展会暂停并提示。技能消息失败不会回退全局输入。日志包含 `hybrid_focus_acquired` / `hybrid_movement_released` / `hybrid_input_error`。这是会切到游戏并留在前台的实验模式，输入与焦点校验并非原子操作，也无法区分同时按下相同方向键等竞态，不能保证零误触。默认配置不变，需手动选择此模式并实测。
- **独立后台（实验）**：`input.delivery=window_message`，只向游戏输入窗口投递 `WM_KEYDOWN/WM_KEYUP`，搭配 `PrintWindow` 客户区截图；不会自动切前台或置顶，失焦时隐藏游戏 HUD。支持窗口消息且失焦后继续绘制的客户端才可使用；游戏窗口需保持非最小化。截图超时、失败或空白会暂停，不回退到桌面截图或全局扫描码。Windows 接收消息不等于游戏成功施法，请实际确认移动、攻击和 Buff。现有 `postmessage/window` 配置别名仍指向旧兼容后台，新模式请明确使用 `window_message`。
- **后台移动兼容尝试**：位移使用约 0.10 秒按下 / 0.05 秒抬起的脉冲，产生新的方向键按下事件；普通技能/转向短按与 classic 扫描码不变。`movement_progress` / `periodic_step_verified` 表示观察到了正确方向的小地图位移（不是客户端按键回执）；`movement_failed` 表示未验证成功，需检查客户端兼容性、地形或角色状态。程序不通过抢焦点、全局按键、注入或驱动强行移动。
- **2026-09-05 本机实测限制**：NewMaple 失焦时攻击可执行，但三轮右移脉冲（0.12/0.24/0.36 秒）均未观察到小地图位移，助手按设计暂停。因此当前纯窗口移动仍未验证可用，不能当作已经支持后台回位；上述位移检测与失败保护不等于解决了客户端兼容性。
- **独立兼容探针**：`python -m mbv.movement_probe` 默认仅列出 NewMaple 输入窗口；明确要求实测时才加 `--enable-input --confirm-bot-stopped`。必须先停止挂机及其它发键器、确认角色左右均为安全平台，并保持游戏后台且非最小化。探针比较 PostMessage/有超时的 SendMessage、标准/非扩展/旧式零参数、重复按下状态位，共 8 种组合的左右键（16 组、每组 0.3 秒）；只向已确认游戏进程的窗口投递，不改变正式配置。检测到位移立即停止供人工复核；F9、游戏回前台、手动方向键、标记歧义或总时限均会中止。日志位于 `logs/movement-probe-*.json`，API 成功不等于移动成功。
- **线程键盘状态共享探针**：在上述命令添加 `--shared-key-state`，改为测试 `AttachThreadInput + SetKeyboardState` 的“仅共享状态”和“共享状态加 PostMessage”两种模式，各测试左右方向，每组 0.3 秒。仍须显式添加两个输入确认参数，完全退出原挂机会话并释放 F9；测试期间暂勿操作键鼠。每组使用一次性子进程，父进程独立检查焦点、手动输入与超时；正常及异常路径均清除本组方向键状态并解除附加，失败会报告，不接入日常挂机。线程附加可能重置键盘状态，不能保证完全无干扰；如果子进程超时被强制终止，需人工检查游戏是否仍按住方向键。共享状态读回成功只证明 API 层，不证明游戏使用该状态，也不是修改 GetAsyncKeyState/DirectInput 的办法。附加期间不使用同步 SendMessage，因为共享输入队列下其超时保护不可靠。
- **前台短步探针**：`python -m mbv.foreground_move_probe` 默认只读；仅在明确授权且原挂机退出、右侧安全时添加 `--enable-input --confirm-bot-stopped`。它记录原前台窗口，短暂激活游戏、验证焦点后向右 0.2 秒，释放方向键并尝试恢复原窗口；失败即停止，不自动重复或返回原安全点。历史实测确认前台右移有效，但恢复浏览器失败；新增混合模式提供限时保护及失败停机，并不意味着该系统限制已消除。不要把短步成功等同于完整混合挂机可用；结果见 `CODE_REVIEW.md` 和 `logs/foreground-move-probe-*.json`。
- **挂机时强制游戏窗口置顶**：默认开启，避免普通窗口覆盖识别区；按 F8 暂停、安全停机或退出程序时自动取消置顶。关闭后，后台按键模式不会在启动时抢前台或置顶；前台按键模式仍要求游戏保持前台。

独立后台的只读截图诊断（不发送按键）：

```bat
.\.venv\Scripts\python.exe -m mbv.background_probe --profile newmaple --samples 3
```

输出截图耗时、窗口是否前台、姓名板分数和身份分。请在暂停旧助手后测试失焦及遮挡场景；分数正常只说明画面可识别，不证明后台输入受支持。PrintWindow 可能返回客户端缓存画面，目前不能保证识别出所有画面冻结情况，也不支持最小化运行。窗口截图进程的 CPU/内存暂未计入面板的主进程统计。

识别不准时：

- 误把木板、特效当怪 → 先删除旧模板并按“主体四周留少量背景”的方式重采；仍有固定误框时在对应怪物分类中采集过滤项，也可提高怪物识别阈值（约 0.75～0.90）或轮廓权重。
- 找不到自己 → 先重采小地图玩家标记；若提示颜色命中多个位置，请点黄色标记最亮的中心。橙色虚线玩家框表示“小地图几乎没动，正在短时沿用上次视觉位置”；如果标记已经移动、持续超过 0.2 秒或仍停机，请重采姓名板 / 头部 / 称号及对应脚底点，并保证游戏分辨率没变。
- 改过窗口大小 → 启动会被阻止；按左侧状态逐项重采。坐标依赖项会自动失效，已有模板图片不会被删除。

## 8. 做不到的事

- 不会爬绳、跳层、换图、过门。
- 不识别死亡、断线、背包满、对话框。
- 游戏最小化后无法截图，会停机。
- 不注入、不改内存；无法在「完全切到浏览器且客户端检查前台」时继续控角色。

日志在 `logs` 目录。启动失败时，同目录会有 `crash-*.txt`。

### “小地图已定位，等待画面定位恢复”的诊断

姓名板被挡住时仍可由头部接替：头部半分辨率漏检会在旧位置附近用原图复核；已确认本人、唯一小地图标记和背景稳定时，恢复确认允许在 0.9 秒内累计至少 3 次头部命中，中间最多漏 1 帧。漏检帧不会凭旧位置恢复攻击，移动、候选冲突或超时会清空确认。黑白姓名板另用灰度与轮廓匹配，避免颜色差值全零导致模板失效；识别门槛和身份验证未降低。

这个提示表示小地图标记仍可用于导航，但没有可用于攻击的可信屏幕位置，不等于小地图漏检或程序卡死。不要直接降低身份阈值，或把小地图位置当作攻击锚点。

默认开启只读定位诊断，**更新代码后需要退出助手并重新启动**：

- 挂机期间真实视觉连续缺失至少 2 秒，自动在 `logs/localization/session-时间-编号/` 保存 JSON 文字记录和原始战斗区、小地图 PNG；不截取整个桌面、不上传。
- 同编号的 `0001.json`、`0001-combat.png`、`0001-minimap.png` 属于同一帧。留样包含最近正常帧、丢失约 2/7/12 秒和恢复帧；短暂闪烁不写文件。后续持续丢失每 5 秒写文字。暂停以 `interrupted` 结案，不算作长时间挂机故障。
- JSON 中 `passes` 包含倍率、ROI、门槛、前 16 个模板最高分位置（包括低于门槛的匹配），及姓名身份校验结果；`before/after` 是确认链与锚点状态；`first_failure` 保留首个失败帧的文字证据，`recent_frames` 保留最近 32 帧简要状态。所有检测框坐标相对战斗裁剪区，`combat_rect` 是裁剪区在客户区的位置。
- `minimap_check` 记录标记相对固定基准的位移、背景是否通过、时限；`state` 是执行动作后的实际状态。`sample_unchanged_seconds` 仅表示稀疏采样像素没变，**不能单独证明截图冻结**。
- 每个助手实例最多保存 60 组图片；队列满时丢弃诊断任务并计数，不等待磁盘。整个 `logs/localization` 达 256 MiB 时停止诊断并提示，不自动删除旧证据、不影响挂机。图片未保存的原因见 `image_status`。可自行归档该目录后重启恢复留样。

再次发生时记一下时间，保留对应会话日志和诊断子目录；最好先不要重采模板，便于对照当时的素材。诊断复用已有匹配结果，不增加模板扫描，不改变定位、攻击、输入模式。若要关闭，在个人配置中设置 `"diagnostics": {"player_localization": false}` 并重启。
